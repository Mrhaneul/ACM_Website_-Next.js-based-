# /interest/set-ideas — Project Idea Submission Form

**Date:** 2026-09-14
**Status:** Approved

## Purpose

Let students submit SET project ideas they would want to work on, so ACM can
source and staff projects. Reached primarily by scanning a printed QR code.

## Routes

| Route | Type | Purpose |
|---|---|---|
| `/interest/set-ideas` | public client component | The submission form |
| `/interest/set-ideas/admin` | password-gated client component | Read submissions, export CSV |

## Data model

Collection `setIdeas` in the **main** Firebase project (`acm-website-459ef`),
written through the existing `db` export in `src/lib/firebase.ts`. No new
Firebase app instance and no new `NEXT_PUBLIC_*` Firebase credentials.

| Field | Required | Type | Notes |
|---|---|---|---|
| `fullName` | yes | string | trimmed |
| `cbuEmail` | yes | string | must match `@calbaptist.edu` |
| `ideaTitle` | yes | string | trimmed |
| `description` | yes | string | textarea, trimmed |
| `category` | yes | string | one of the category options |
| `techInterest` | no | string | free text |
| `involvement` | yes | string | Lead it / Help build it / Just suggesting |
| `submittedAt` | auto | Timestamp | `serverTimestamp()` |

Category options: Web, Mobile, Game, AI/ML, Hardware/IoT, Cybersecurity,
Data, Other.

## Components and boundaries

- `src/lib/setIdeasValidators.ts` — pure module. Exports `CATEGORY_OPTIONS`,
  `INVOLVEMENT_OPTIONS`, the `IdeaForm` interface, and
  `validateIdeaForm(form): string` returning `""` when valid or a
  user-facing message. Depends only on `registrationValidators.isValidCbuEmail`.
  No React, no Firebase, so it is unit-testable in isolation.
- `src/lib/setIdeasValidators.test.ts` — vitest coverage of each rule.
- `src/app/interest/set-ideas/page.tsx` — form UI and Firestore write only.
  Delegates all validation to the validator module.
- `src/app/interest/set-ideas/admin/page.tsx` — password gate, table, CSV
  export via existing `buildCsv` / `downloadCsv`.
- `scripts/generate-qr.mjs` — build-time QR generation. Not part of the app
  bundle.

## Data flow

Submit -> `validateIdeaForm` -> on error set inline message and stop ->
on success `addDoc(collection(db, 'setIdeas'), {...})` -> success screen with
a "Submit another idea" reset.

## Error handling

- Validation failures render inline above the submit button; nothing is written.
- A thrown Firestore error is logged and shown as a generic retry message,
  matching `/register`.
- `loading` disables the submit button to prevent double submission.

## QR code

`public/set-ideas-qr.png`, 1200px, encoding
`https://acm-website-459ef.web.app/interest/set-ideas`.
Generated by `scripts/generate-qr.mjs` using `qrcode` as a **devDependency**
so it never reaches the client bundle. Regenerate with `node scripts/generate-qr.mjs`.

## Firestore rules (manual, out of repo)

Rules for this project are managed in the Firebase console and are NOT
committed here. A `firestore.rules` file is deliberately not added, because
deploying one would overwrite the existing `users` and `projects` rules that
login and the dashboard depend on.

Required console addition:

    match /setIdeas/{doc} {
      allow create: if true;
      allow read: if true;
      allow update, delete: if false;
    }

## Known limitation

The admin password gate is client-side only, so `read` must be public for the
admin table to load. Submitted names and emails are therefore readable by
anyone who knows the collection name. This matches the existing
`/register/admin` design and is accepted for low-sensitivity idea data. To
harden later, require Firebase Auth for reads and sign the admin in.

## Testing

- `npm test` — validator unit tests.
- `npm run build` — type and build check.
- Post-deploy manual check: submit a real entry, confirm it appears in the
  admin table, then delete it.

## Deploy

`npm run build` then `firebase deploy --only hosting` against the default
`acm-website-459ef` project.
